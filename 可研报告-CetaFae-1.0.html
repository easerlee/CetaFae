二、Win10/11 兼容性与系统限制

  • Win10 需 ≥1809 才有 Windows.Graphics.Capture；Win10/Win11 的 UIA 树差异需两套用例。
  • UIPI：普通权限进程无法对管理员窗口做 UIA、发消息或拖放：与“不请求管理员权限”直接冲突（见 B1）。
  • 全屏独占 DirectX、UAC 安全桌面、锁屏：悬浮层不可见、不可交互。
  • DRM/受保护内容窗口截图为黑屏。
  • 全局钩子、屏幕捕获与模拟输入同时使用时，极易被 360、火绒和 Defender 判定为可疑程序，因此需要签名并进行白名单沟通。

四、性能红线（PRD 仅给 NFR-01，其余为建议值）

  • 待命内存 ≤ 90MB、CPU 均值 ≤ 0.3%（零定时器或 ≥1s 轮询）、零磁盘 I/O
  • 冷启动 ≤ 1.5s；悬浮球拖拽响应 ≤ 16ms；描边绘制 ≤ 50ms
  • 识别链路 P95 ≤ 3s（NFR-01）；安装包 ≤ 80MB；卸载后残留文件与注册表项均为 0
  • 崩溃隔离天然满足：全部操作在目标进程外，不注入、不 Hook 目标进程

五、技术阻塞点 / 高代价项

  • B1 UIPI 硬墙：管理员窗口不可交互。必须显式声明“不支持管理员窗口”，否则测试必挂。
  • B2 .docx 还原与“滚动高亮”互斥：文件被 WPS 打开时外部改写会被覆盖或其云同步覆盖，快照完整性（TC-3）不可判定。建议 1.0 仅处理未占用文件。
  • B3 权限模型无法由 OS 实现：Windows 不存在 macOS 式“屏幕录制”、“辅助功能”授权，“拖放时申请、脱离即停”只能自建开关 + 明示。
  • B4 云端 AI 成本 vs 开源无预算：每帧识别都调用“已备案云端接口”，无配额与计费方案 → 建议本地 OCR 兜底 + 用户自带 API Key。
  • B5 全屏独占、安全桌面和 DRM 场景天然不可覆盖。

鲸汐 CetaFae 1.0 架构与工程可维护性评估

一、分层架构建议

  • UI 层：悬浮球、描边、解释浮层、提示条。只负责渲染与输入，不包含业务判断。
  • 能力层：识别 → 分档决策 → 解释 → 快照 → 执行 → 还原/冲突态。按端口-适配器组织：领域接口在内，Windows 实现（UIAutomation、截图、文件 API）在外。
  • 扩展机制：1.0 不引入运行时插件加载，改用“声明式支持清单 + 档位策略表”数据驱动。
  • 本地存储：版本化快照、配置、菜单入口；单机运行、无跨会话记忆。
  • 云服务：单一 Provider 接口 + 可关闭开关，本地降级路径必须存在。
  • 技术栈权衡：.NET/WPF（UIA、截图、文件快照原生，体积小、误报低）优先于 Electron（生态熟但体积大、误报高）。

二、1.0 与未来的边界

现在必须留的口子：① 识别器/执行器/快照器各一个接口；② 档位策略与支持清单外置为版本化数据文件；③ 快照 schema 带版本号与迁移位；④ 云 Provider 可拔插，默认关闭仍可运行。 现在不做：运行时插件框架、多显示器/DPI、跨会话记忆、本地推理。理由：无第二个实现就不抽象（Rule of Three）。

三、第三方依赖风险

  • 协议：仅收 MIT/Apache-2.0，禁 GPL/AGPL 进分发；CI 许可证扫描。
  • 停维护：Windows 生态库易停更；锁版本 + 依赖清单 + 替代预案。
  • 体积：不捆绑浏览器运行时。
  • 杀软误报（最高危）：未签名 exe + 全局钩子 + 自动写文件是误报三要素。缓解：不用全局键盘钩子、不注入进程、只走 UIA 与文件 API；代码签名成本未知。

四、团队能力匹配

人力：人数、分工、预算、上线时间均未提供，无法判断产能与排期，以下仅针对“架构复杂度对 vibe coding 协作的可维护性”。

  • 可维护：单进程模块化单体、约 5 个模块、无自建后端、无活动部件编排。
  • 不可维护：微服务、运行时插件框架、自研云、多端。
  • 缺口影响：预算未知 → 无法判断签名证书与返工投入是否可承受；工期未知 → 无法安排“最晚可逆点”，也无法决定是否先出降级版（只讲解不执行）。

五、测试可行性

  • 难测：拖拽吸附、描边定位、浮层避让、焦点、UIA 跨应用不稳定、时序 flaky。
  • 可测：档位决策、快照 diff/还原幂等、解释模板、支持清单匹配、冲突判定——纯函数单测。
  • 建议：核心逻辑与 UI 解耦 ≥70% 可单测；UI 用录制回放 + 截图比对；云用契约测试 + mock；TC-1～TC-5 做成 CI 门禁。

六、结论：有条件可行

前置条件：

  1. 单进程模块化单体，不拆服务；
  2. 端口-适配器 + 数据驱动清单，禁硬编码分支；
  3. TC-1～TC-5 通过前，FR-07/FR-11 不得进 P0 发布（现基线矛盾）；
  4. 依赖白名单 + 许可证扫描 + 版本锁定；
  5. 先解决 6.1/6.2「档位可见性」矛盾再冻结接口。

鲸汐 CetaFae 1.0｜安全·隐私·合规评估

一、权限与能力风险（等级｜防线）

  1. 全局热键/键盘监听｜高：低级键盘钩子可录全部击键。只允许按 RegisterHotKey 注册单个组合键，禁用 WH_KEYBOARD_LL，不缓存按键内容。
  2. 屏幕捕获｜高：可摄密码、聊天、金融信息。仅拖放瞬间抓用户指认的单一窗口；不全屏、不连续、不落盘、用完即毁；界面常显采集态。
  3. 剪贴板｜高：读=密码/验证码外泄，写=篡改。1.0 不读、不监听变更；只写且写前预览。
  4. 文件写入｜高：可损坏文档。仅限指认的单文件；快照+校验和后原子替换；拒系统目录与可执行文件；失败可见。
  5. 自启动/常驻｜中：隐蔽驻留难关闭。默认关、手动开、一键关；仅托盘常驻，无服务/驱动/计划任务。
  6. 网络外发｜高：屏幕与文件内容外流。默认离线；出网仅限用户点「做」并逐次告知；无遥测埋点；TLS1.3+固定域名白名单。
  7. 提权｜高：asInvoker，绝不请求 UAC。

二、合规必须动作（PIPL/CSL）

  • 屏幕内容/文件内容/云端处理三类单独同意，首启分层告知，不默认勾选。
  • 最小必要：只处理当次单一窗口或文件，无后台巡检、无跨会话记忆。
  • 本地优先：识别与 PII 检测在本地完成。
  • 可撤回：读写权限用完即释；一键删本地缓存与日志；日志不含屏幕原文与文件内容。
  • 补齐空白（当前全缺）：隐私政策、用户协议、处理者名称、保留期限、联系方式与投诉渠道——缺失即不得发布。

三、AI 云端接入

  • 出境｜高：境外模型须单独同意+安全评估/标准合同（PIPL 38 条）。1.0 只用境内已备案接口。
  • 留存｜高：合同写明零留存、不用于训练；本地不存请求体。
  • 脱敏｜中：上传前本地遮挡账号/密钥/PII，只传必要片段；返回做输出校验。
  • 注入｜中：窗口内容视为不可信数据，不作指令执行。

四、分发与信任

  • 代码签名｜高：必须 OV 以上+时间戳。无签名即 SmartScreen 红屏、杀软高误报、用户不敢装；EV 仅缩短声誉积累，非必需。
