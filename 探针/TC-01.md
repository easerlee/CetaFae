# TC-01 控件坐标可获取

日期：2026-10-26　探针：`src/CetaFae.Probe --uia`　台架：Windows 11 设置（暂停更新页，中文 UI）

## 结论

设置页这一处成立：控件树可读、坐标可用、静置零抖动、读取 270ms。这证明的是「这一页读得稳」，不是「所有设置页可读」，也不是「首次就能选对目标控件」。

Edge 上当前探针没有取到网页内容。这只说明本次环境与读取路径的结果，不能据此判定平台零覆盖，见下节。

## 设置页数据

| 项目 | 结果 |
|---|---|
| 快照 | 5 次，每次 105 个节点，节点数与顺序完全一致 |
| 坐标 | 93 个元素有矩形且 5 次完全一致（抖动 0px）；12 个元素始终无矩形 |
| 可点元素 | 38 个，可点元素里没有一个是匿名的 |
| 读取耗时 | 268–272ms（整棵树，深度 14，Node 上限 5000） |
| 同名可点控件 | 2 组：「系统」是 ListItem + MenuItem，「Windows 更新」是 Button + ListItem |

任务「暂停更新」相关元素（供 OCR 对账参考，不作为真值盲用）：

| 元素 | 矩形 | 可点 |
|---|---|---|
| Group `暂停更新`（AutoId `…_PauseUpdate3_ButtonEntityItem`） | 1399,538,1000,69 | 否 |

当前机器已暂停更新到 2026/10/29，页面上没有「暂停更新」入口，只有「继续更新」与调整日期的按钮。样本要按「任务 + 当时状态」建，不能只按任务名计数。

## 复核：鼠标与空壳

- 首轮 5 次快照 SHA256 完全相同（`DE0799A2…`，27492 字节），期间鼠标在动。指针位置不进控件树，设置页也没有悬停才出现的元素。这条只对设置页成立。
- 复核时设置窗口被关闭，`AutomationElement.FromHandle` 不报错，只回 1 个节点。探针当时把空壳当成了正常结果。三类状态已分开记：`uia_window_gone`（句柄失效）、`uia_read_failed`（读取异常）、`uia_small_tree`（节点偏少，仅告警，不据此判窗口失效——简单弹窗本来就只有几个节点）。
- 重新打开后取 3 次，三次字节一致。与首轮的差异仅来自窗口整体平移（+756,+67），元素集合与相对位置一致；底部一个帮助链接被窗口下沿裁掉，高度 15px → 6px。

## Edge：当前探针未取得网页内容

夹具页 `logs/uia-fixture.html` 含可点按钮、禁用按钮、链接、输入框、下拉、复选框。四种探法都只拿到浏览器外壳：

| 探法 | 结果 |
|---|---|
| 顶层窗口（`0x20BBE`，夹具页在前台） | 58 个节点，全是标签栏、工具栏、地址栏、收藏夹、窗口按钮；网页元素 0 个 |
| 渲染子窗口 `Chrome_RenderWidgetHostHWND`（`0x20BC0`） | 1 个节点，`Chrome Legacy Window`，无子元素 |
| 加 `--force-renderer-accessibility` 重启 | 仍 58 个节点，网页元素 0 个 |
| 向渲染子窗口发 `WM_GETOBJECT(OBJID_CLIENT)` 后再取 | 无变化 |

这条不能写成「Chromium 网页只能走 MSAA」，也不能写成「平台零覆盖」。两条已查事实与之相反：

1. Chrome 从 138 起在 Windows 上默认启用原生 UIA（[Chrome for Developers](https://developer.chrome.com/blog/windows-uia-support-update)），Edge 156 在范围内。
2. 本机没有 Edge 的 `UiAutomationProviderEnabled` 策略项（HKLM 与 HKCU 均不存在），没有被回退成旧模式。

`UiaClientsAreListening()` 同时返回 true。平台侧应该给得出树，问题更可能在本探针的读取路径上。

### 待查（下一步）

按「先分责任、再谈补通道」的顺序：

1. 独立检查工具观察同一夹具页。能看得到、探针看不到 → 查探针读取路径；两者都看不到 → 查浏览器状态、配置与环境。
2. 探针侧先做三个廉价排查：改 `RawViewWalker`（`--uia-raw`）、从浏览器顶层窗口取 `RawView` 子树、确认取树时目标页在前台且已加载完成。
3. 以上都不成立，再考虑 MSAA 补测。现在不据此确定双通道架构。

`Chrome Legacy Window` 这个类名只说明该 HWND 挂着 MSAA 桥，不足以证明内容只能通过 MSAA 取得。

## 边界

- 只测了设置页一处。其余设置页、系统弹窗、Edge、办公软件都没测。
- 滚动懒加载没测；最大化与分屏时矩形是否一致没测。
- 管理员权限窗口读不到（UIPI），属平台约束，需在清单外显式声明。
- 本机没装 WPS，`.docx` 关联到 Word，见 `探针/环境.md`。
