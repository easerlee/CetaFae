# TC-01 控件坐标可获取

日期：2026-10-26　探针：`src/CetaFae.Probe --uia`　台架：Windows 11 设置（暂停更新页，中文 UI）

## 结论

设置页这一处成立：控件树可读、坐标可用、静置零抖动、读取 270ms。命中率还没算——命中率要按清单逐条建样本，目前只完成了 1/19。

## 数据

| 项目 | 结果 |
|---|---|
| 快照 | 5 次，每次 105 个节点，节点数与顺序完全一致 |
| 坐标 | 93 个元素有矩形且 5 次完全一致（抖动 0px）；12 个元素始终无矩形 |
| 可点元素 | 38 个，可点元素里没有一个是匿名的 |
| 读取耗时 | 268–272ms（整棵树，深度 14，Node 上限 5000） |
| 同名可点控件 | 2 组：「系统」是 ListItem + MenuItem，「Windows 更新」是 Button + ListItem |

目标任务「暂停更新」的定位结果：

| 元素 | 矩形 | 可点 |
|---|---|---|
| Group `暂停更新`（AutoId `…_PauseUpdate3_ButtonEntityItem`） | 1399,538,1000,69 | 否 |
| Button `更新已暂停，直到 2026/10/29…`（AutoId `…_PauseUpdate3_Button`） | 2264,557,118,32 | 是（Invoke） |

## 发现

1. **名字不够用，必须带类型或 AutomationId**。两组同名控件的类型不同，只按 Name 匹配会选出两个候选，指哪一个是猜的。AutomationId 在设置页带页面语义（`SystemSettings_MusUpdate_PauseUpdate3_*`），比名字稳；但这套命名是 XAML 应用的特征，Edge 与 WPS 未必有。
2. **无坐标不等于不存在**。12 个无矩形元素全部 `IsOffscreen=true`，包括页脚、垂直滚动条和窗口的最小化/最大化/关闭。它们真实存在，只是不在可视区。C-4 的兜底逻辑必须区分两种「找不到」：树里没有这个控件，和控件在滚动区外。混在一起会把可指的目标误判成不可指。
3. **同一任务在不同状态下是不同的样本**。这台机器的更新已经暂停到 2026/10/29，所以页面上是「继续更新」和一个调整日期的按钮，不是「暂停更新」入口。按任务名建样本会失效，得按「任务 + 当时状态」建。
4. **语言不统一**。设置内容全是中文，窗口的最小化/最大化/关闭却回英文（`Minimize`/`Maximize`/`Close`）。名字匹配不能假设单一语言。
5. **3 秒预算里读树只占 9%**。105 节点 270ms，剩下的时间都归识别与网络。这条让 NFR-01 有余量，但节点数会随应用膨胀，Edge 的页面树通常上千节点，要单独测。

## 边界

- 只测了设置页。Edge（Chromium 的 UIA 要另开可访问性）、WPS、系统弹窗都没测。
- 滚动懒加载没测：页面往下滚之后新出现的元素是否带坐标，未知。
- 最大化和分屏时矩形是否仍然一致，没测。
- 管理员权限窗口读不到（UIPI），这条是平台约束，不必测，但要在清单外显式声明。
- 本机没装 WPS，Office 才是 `.docx` 的关联程序，见 `探针/环境.md`。

## 复现

```powershell
dotnet build src\CetaFae.Probe\CetaFae.Probe.csproj -c Debug
# 快照 5 次
1..5 | ForEach-Object { dotnet run --project src\CetaFae.Probe -- --log logs --uia "设置" --dump "logs/uia-stab-$_.jsonl" }
# 统计抖动、可定位率、同名控件
tools\uia-stats.ps1 -Dumps (Get-ChildItem logs\uia-stab-*.jsonl).FullName
```
