# TC-06 拖放与标记不抢焦点

日期：2026-10-26　探针：`src/CetaFae.Probe`　台架：记事本（`target.txt`）

## 结论

合成输入下，拖拽、松手、Esc 全程不改前台窗口。真人拖动与目视项（标题栏、输入光标）还没做，这一步结论只能当「没发现抢焦点」，不能说「验证通过」。

## 数据

| 项目 | 结果 |
|---|---|
| 有效试验 | 7 轮（共 4 批；2 轮因目标不在前台作废，已单独记 `trial_miss`） |
| 拖动前后前台窗口 | 7/7 未变，全程停在靶窗口句柄 |
| Esc 中断 | 7/7 命中，`RegisterHotKey` 收到 VK_ESCAPE，描边隐藏、事件钩子解除 |
| 标记残留 | 7/7 `overlayVisible=false`，退出路径同样为空 |
| 落点命中 | 5/7 落在靶窗口；2 次落在覆盖窗口上，是测试台没锁前台，不是产品行为 |

## 边界

- **Esc 只能靠全局热键**。悬浮球设了 `WS_EX_NOACTIVATE`，永远拿不到键盘焦点，`PreviewKeyDown` 这条路不存在。能用的只有 `RegisterHotKey`（本轮采用）或低级键盘钩子（需求 10.1 明确不用）。副作用：注册期间 VK_ESCAPE 被产品截走，其他程序收不到。这个副作用本轮没测，但按 RegisterHotKey 的语义必然存在。
- **合成输入不等于真人**。合成拖拽的按下事件比光标晚到约 76px（消息队列排队），真人的按下与移动是串行到达。焦点行为在两者之间未必一致，验收记录里必须分开写。
- **只测了记事本**。Edge、WPS、Win11 设置页都没上；需求 TC-6 要求三个场景各 5 次。
- **目视项未做**：目标窗口标题栏是否变色、输入光标是否跳走。程序测不出来，要靠录屏回放。
- 设了 `WS_EX_TOOLWINDOW`，任务栏不出现条目，这一点没单独验。

## 已确立的实现细节

- 悬浮球与描边层都要 `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`，且 `ShowActivated=false`。
- 落点判定要先把自身窗口临时设成 `WS_EX_TRANSPARENT` 再 `WindowFromPoint`，否则命中的永远是贴在指针底下的自己。
- 桌面类窗口（`Progman`/`WorkerW`/`Shell_TrayWnd`）要显式排除，否则会把桌面当成目标窗口吸上去。

## 复现

```powershell
# 需要鼠标：约 20 秒，先把靶窗口拉到前台
$shell = New-Object -ComObject WScript.Shell; $null = $shell.AppActivate('target.txt')
dotnet run --project src\CetaFae.Probe -- --log logs --auto "target.txt" --trials 2 --dwell 700
```
